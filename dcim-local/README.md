# AIDC · 4F DCIM 本地 Prototype

依管理介面參考及平台架構圖建立的可操作展示版本。使用既有 4F Draco GLB，A 區 11 櫃、B 區 22 櫃。所有遙測值、門禁紀錄、帳號及 IT 設備清單都是展示資料；CCTV 依使用者指示採靜態示意照片。

## 啟動

需要 Node.js 24（本機已驗證 24.22.0）。不需要 Docker。

```sh
cd '/Volumes/project backup/claude/AIDC/dcim-local'
npm ci
npm run build
npm start
```

開啟 http://127.0.0.1:3001 。已安裝依賴並建立 dist 後，只要 `npm start` 即可。這個程序需持續運行，Ctrl+C 結束。所有前端依賴、Draco WASM、模型、字型系統 fallback 及照片都在本地，不需執行期外網 CDN。

開發熱更新：`npm run dev`，開啟 http://127.0.0.1:5173 。API 同樣使用 3001；請不要同時執行 `start` 和 `dev` 以免連接埠衝突。

驗證：`npm test`。建置：`npm run build`。

## 資料與模型

- `public/models/4f.glb`：Draco 壓縮模型，約 737 KiB。33 個機櫃根節點使用 `4F-A-01…11`、`4F-B-01…22`，帶有 glTF extras `Zone`、`Rack_number`。
- `public/draco/`：從已安裝的 Three.js 套件複製，提供本地解碼器。
- `public/cctv/`：現有模型渲染和參考影片截圖，統一標記靜態模擬。
- `server/domain.mjs`：種子資產、模擬遙測、U 位驗證規則。
- `server/store.mjs`：SQLite 與交易、操作紀錄。
- `server/index.mjs`：本地 HTTP API、SSE 推播、正式建置檔案服務。
- `data/dcim.sqlite`：首次啟動自動建立；資產、告警確認及展示使用者會保留。執行中可能另有 WAL／SHM 檔案。
- `docs/LOCAL_ARCHITECTURE.md`：介面與系統分層、資料欄位、後續串接規劃。

畫面遙測約每 3 秒更新。固定告警由種子資料建立，沒有正式告警規則引擎；確認告警只改變處理狀態，**不會清除模擬設備異常**。用電曲線為固定展示序列，不是累積歷史；日用電展示數字由同一 24 小時序列計算。機櫃的 42U 資產是 UI 展示用清單，並未修改 GLB 機櫃內部幾何。

## 範圍

本版只在 `127.0.0.1` 提供服務，作為本地展示 prototype。未接入真實 Modbus／BACnet／SNMP／NetFlow／門禁／消防；未實作遠端控制、真實登入、多人同步衝突處理或正式運維機制。後續內網部署要先完成身分驗證、RBAC、資料驗證、備份及現場協定對接。

## 操作示範

1. 總覽切換 Zone B，點擊機櫃或告警的定位箭頭。
2. 在「機櫃配置」點設備，將 U 位移至空白區，儲存後立即更新 42U 圖。
3. 輸入重疊 U 位，應顯示錯誤且不覆寫原資料。
4. 「系統監測 → 門禁」切換 CCTV 照片並點擊放大。
5. 確認告警，再於報表頁查看操作紀錄、下載 CSV。

建議展示視窗 1440×900 以上。窄螢幕會調整面板與導覽；3D 需要支援 WebGL 的瀏覽器。

新增操作：主選單「能耗管理」提供 PUE 目標／警示設定、6／24 小時模擬用電比值及 CSV。中央可切換溫度熱圖、功率熱圖或關閉，右側可調透明度並選取排行中的機櫃。所有讀值與熱圖均為模擬展示，設定保存在本機 SQLite。「更多」選單可進入資產管理、服務關聯、報表分析及使用者管理。

## RFI 展示操作

主選單「GenAI 決策」：建立情境 → 產生分析 → 查看方案 → 執行條件檢查 → 勾選確認並執行模擬降載 → 推進時間至 T+10 → 復載第一台 → 再推進 5 分鐘 → 復載第二台 → 下載 HTML 事件報告。

範圍僅 4F A／B 區。正常情境由 AC-A-02、AC-B-02 各降低 8 kW，需量由 252 降至 236 kW。T+10 劇本基準需量回落至 218 kW，允許分批復載。另有高溫阻擋、離線阻擋、命令失敗及回復情境。未執行前可取消事件，事件保存在 SQLite，同時只允許一個未結束事件。

所有分析、命令與回授均為模擬，未呼叫 LLM 或現場設備。需量不是實際 15 分鐘積分，冷卻保護以空調輸入功率代理值示範，並非熱力模型。節能、健康與時間電價分析均有示範假設及來源說明，與既有總覽遙測分開。

核心檔案：shared/rfi.mjs、src/Rfi.jsx、tests/rfi.test.mjs。

## 能源歷史、月報與工單

- 「更多 → 能源歷史與月報」：選月份及 A／B 區，查看每日用電、能源分類、電能加權 PUE，產生分析與下載 HTML 月報。不同月份依日均值比較；2026-11 僅含 1–10 日，基準月也取相同日期。歷史資料為固定模擬分表，並非即時遙測累積。
- GenAI 對話可查詢「上月 B 區耗電分析」，使用與月報相同的資料及計算；分析使用規則及範本，沒有呼叫 LLM。
- 「告警總覽 → 告警轉工單」或「更多 → 工單管理」：建立指派、開始處理、填寫結果、提交審核，再切換審核人核准結案或退回補件。流程與紀錄保存在 SQLite，具有狀態與版本檢查；人員切換僅為展示，沒有真實登入授權。工單結案不清除來源告警。
- `tests/operations.test.mjs` 驗證能源計算、部分月份比較、工單角色／狀態限制、退回重送、版本衝突及持久化。

工單介面參考 TaipeiCityHall 的 WorkOrderDialog：以「報修登記 → 指派派工 → 送出完成」彈窗建單，告警自動帶入 4F 區域與設備，可設定優先級、故障描述、通報人、承辦廠商、受派／驗收人及完成日。主頁提供狀態統計、關鍵字與區域篩選、流程進度及處置時間軸。既有工單仍可讀取。

工單管理預設為四欄看板，可切換清單。卡片依逾期、優先級及更新時間排序；支援關鍵字、區域、受派人、優先級與逾期篩選。點擊卡片展開詳情，執行處理／驗收後依實際狀態移欄。

工單後續操作：受派人可新增處理紀錄而不改變狀態。切換展示操作人員為管理員後，可展開「派工與期限管理」，填寫原因再調整期限；未送審工單可改派給其他有效維運人員，改派後回到已指派並保留歷程。已結案工單不可改派或修改期限。可下載篩選清單 CSV 及單張工單 HTML 處置紀錄。以上為展示角色流程，並非正式身分驗證。

## 容量規劃（RFI 8.3.16 首版展示）

### 容量方案轉上架工單
